# 启真问智比赛定位与展示策略

## 1. 项目定位

本项目参加教育教学智能体赛道。

一句话：

> 基于智云课堂字幕的课程教辅生成智能体，把课堂回放沉淀为可阅读、可复习、可导出的结构化课程资产。

---

## 2. 不要讲太高级

不要把项目包装成：

- 重构教育生态。
- 全流程个性化学习平台。
- 完整师生机协同系统。
- 自动教材出版工具。

比赛里更容易讲清楚的是：

> 老师讲了一学期，智云里留下字幕和 PPT。我们把这些材料自动整理成一份讲义草稿。老师能改，学生能看，课程资产能沉淀。

---

## 3. 展示重点

现场/视频演示只展示一条路径：

```text
选课 → 获取资料 → 生成中 → 打开讲义 → 导出
```

不要让评委在聊天框里随便问。开放问答风险太高，而且会让产品变普通。

---

## 4. 评分维度对应

| 评分维度 | 对应话术 |
|---|---|
| 创新性 | 不是通用 RAG，而是面向课堂字幕 + PPT 的课程成书工作流 |
| 教学应用价值 | 降低教师整理讲义成本，帮助学生复习课程结构 |
| 技术实施质量 | 自动获取、清洗、对齐、结构化、生成、导出完整 pipeline |
| 用户体验与推广性 | 输入只是一门课，输出是一份可读讲义，流程简单 |
| 师生机协同 | 教师提供课程与审核，学生使用讲义复习，机器完成资料整理 |

---

## 5. 版权口径

> 系统仅处理教师授权或学生本人有访问权限的课程资料，生成结果用于课程内部教学改进与个人学习，不默认公开原始字幕、PPT 或完整课程内容。

---

## 6. 演示兜底

必须准备：

- 一份预生成讲义。
- 一份录屏。
- 本地缓存的字幕和 PPT。
- 无网络时也能打开的静态网页。

## 7. 现场演示脚本（5–8 分钟）

演示目标不是展示“模型正在打字”，而是让评委看懂一份课程资料如何变成可检查、可恢复的课程资产。

### A. 导入与快照（约 1 分钟）

1. 打开“资料集”，展示字幕、课件或上传文件分别作为资源进入资料集。
2. 创建输入快照，强调本次运行只读取快照中的版本；同一资料集可以再次创建新快照并生成历史版本。

### B. 运行过程可视化（约 2 分钟）

1. 从快照进入生成，展示阶段条：解析 → description → 主 Agent 规划与 Tag → 上下文组装 → 章节 Agent → 全书合成 → 渲染。
2. 展示章节 Agent 的并行状态，以及右侧运行轨迹中的时间、错误类型和重试信息。
3. 展示模型调用统计：请求次数、输入/输出/总 Token、失败请求、重试次数、累计耗时。中转站不返回 usage 时，明确说明系统不会伪造 Token。

### C. 异常与恢复（约 1 分钟）

演示预先准备的失败状态或录屏，不在现场故意消耗 API：

- 失败状态标明是认证、限流、超时、网络或 JSON 解析问题。
- 点击“恢复或重试”，说明系统复用已完成章节，只处理失败或未完成章节。
- 服务重启或手动停止后，任务显示“已中断”，可以从任务详情恢复。

### D. 质量与产物（约 2 分钟）

1. 打开质量报告，展示每章来源覆盖、缺失来源和待处理警告。
2. 标记已确认或重新生成单章，说明人工确认仍是质量闭环的一部分。
3. 打开最终讲义，展示前言、知识地图、术语表、要点索引和章节来源；最后从产物页查看本次生成历史。

### 现场安全边界

- 现场只使用一份小型资料集或已经完成的快照，不直接生成整门课。
- API Key 只保存在本地环境变量，不放进截图、录屏或 Git。
- 真实 API 联调先做单章/小资料集验证；完整比赛演示使用已验收产物兜底。
