# CourseBookAgent 产品交接文档

> 交接对象：后续接手开发的 AI / 队友 / 参赛材料撰写者。
> 文档目的：即使不读取此前对话，也能理解这个"启真问智"教学智能体比赛项目要做什么、为什么做、输入输出是什么、工作流如何设计。

## 0. 一句话说明

**CourseBookAgent 是一个"课程成书"智能体：输入一门课程，系统自动获取智云课堂字幕，经过 AI 生成工作流（字幕压缩 → 全书规划 → 分章撰写 → 全书合成），输出一份可阅读、可导出、像教辅书的课程讲义网页 / Markdown。**

```text
选择一门课程
    ↓
自动获取讲次、字幕
    ↓
每讲压缩为知识点地图（面向聪明主编）
    ↓
全书规划（结构 + 组件规范 + 每章指令 + 写作系统 prompt）
    ↓
分章撰写（主编 prompt + 完整字幕 → 教辅章节）
    ↓
全书合成（前言 + 知识地图 + 术语表 + 要点索引）
    ↓
输出教辅书（网页 / Markdown / PDF）
```

这个项目不是：

- 通用 ChatGPT 套壳。
- 复习陪伴机器人。
- 全校学习平台。
- 从零训练垂直大模型。
- 完整教学评价系统。

核心产品形态：**把一门真实课程自动整理成一本像样的教辅书。**

## 1. 比赛背景

比赛：第二届全国高校"启真问智"教育教学人工智能大赛。

- 赛道：教育教学智能体。
- 作品需基于国内通用大模型或平台工具开发 AI 智能体。
- 关注真实教学场景、教学效率、个性化学习。

比赛叙事：

> 课堂视频、字幕和 PPT 本来是碎片化、低复用的教学过程数据。CourseBookAgent 将这些过程数据自动整理为结构化课程教辅，让教师可以沉淀课程资产，让学生获得可阅读、可复习、可追溯的课程文本。

注意：比赛叙事可以写"师生机协同"，但产品不要被口号拖膨胀。MVP 先做"课程 → 教辅书"。

## 2. 产品切入点

### 2.1 真实问题

高校课程中，智云课堂沉淀了大量课堂录像、字幕、PPT 时间轴，但它们通常只是"回放资源"：

- 学生复习时很难从数小时视频中快速重建知识结构。
- 老师的口述讲解不会自然沉淀为可复用讲义。
- PPT 只有框架，字幕只有口语流，两者分开看都不够完整。
- 人工整理一门课需要大量时间。

### 2.2 核心洞察

课堂材料不是缺内容，而是缺一次结构化加工。AI 的价值在于把课堂讲解整理成可阅读、有重点、可复习的课程文本。

### 2.3 产品定位

> **面向高校课程的 AI 教辅书生成工作流。**

不是"问答机器人优先"，而是"成稿优先"。如果后续要加问答、测验、复习功能，它们都应该依附在生成出的教辅上，而不是取代教辅成为主产品。

## 3. 用户与场景

### 3.1 目标用户

| 用户 | 诉求 | 本产品提供什么 |
|---|---|---|
| 任课教师 | 沉淀课程资产、整理讲义 | 自动生成课程教辅草稿 |
| 选课学生 | 快速复习、重建知识结构 | 有目录、有重点、有来源的课程教辅 |
| 助教/课程团队 | 整理课程资料 | 统一的课程资料处理工作流 |

### 3.2 核心场景

> 一门有智云课堂回放的课程，被系统自动整理成一份可复习的教辅书。

演示流程：

1. 选择课程。
2. 展示系统获取讲次、字幕。
3. 展示生成中的 workflow 状态。
4. 打开最终教辅网页（有目录、重点、易错点、时间戳跳转）。
5. 导出 Markdown。

---

## 4. 输入与输出

### 4.1 输入

最简输入：`course_id` 或 `course_name`。

原则：**不要让用户上传一堆资料。** 输入越简单，产品越像智能体：用户只说"这门课"，系统自己去拿材料。

### 4.2 输出

MVP 输出优先级：

1. **Markdown 教辅**：主产物，易于生成、版本管理、导出。
2. **网页阅读器**：比赛展示友好，支持组件渲染和时间戳跳转。
3. **PDF**：给老师/评委看的成品感（后置）。

教辅书结构：

```text
前言 / 如何使用 / 知识地图 / 学习路径 / 目录
第 N 讲：章节（承上 / 学习目标 / 导读 / 重点 / 概念 / 小节正文 / 易错点 / 小结 / 启下 / 来源）
要点速记 / 术语表 / 来源索引
```

质量底线：

- 像一本可复习的教辅书，不是散乱摘要。
- 每章结构一致，有承上启下。
- 有重点、有易错点、有例题。
- 尽量保留来源信息（字幕时间段）。
- 不胡乱扩写成教材，不假装老师没讲过的内容是课堂内容。

## 5. 核心 Workflow

```text
课程选择
    ↓
课程资料获取（讲次 + 字幕）
    ↓
字幕清洗分块（确定性逻辑）
    ↓
字幕压缩
    - 每讲 → LectureDigest（知识点地图 + 教师流向 + 时间锚点）
    - 面向"聪明的总编辑"，不面向读者
    ↓
全书规划
    - 全书结构（模块 / 章节角色 / 主线）
    - 组件规范（例题框 / Tips / 易错警告 / 步骤）
    - 每章写作指令（ChapterInstruction）
    - 共享写作系统 prompt
    ↓
分章撰写
    - 主编 prompt + 完整字幕 → 带时间戳链接和组件的章节
    ↓
全书合成
    - 前言 / 知识地图 / 术语统一 / 要点索引
    ↓
渲染输出（Markdown / Web / PDF）
```

详细设计见 `docs/WORKFLOW.md`。

## 6. 模块拆分

```text
coursebook_agent/
├── app.py                  # FastAPI 入口
├── config.py               # 配置（LLM / 存储 / zju-scholar）

├── preprocess/

├── agent/
│   ├── digest.py           # 字幕压缩
│   ├── editor.py           # 全书规划（主编）
│   ├── chapter.py          # 分章撰写
│   ├── synthesize.py       # 全书合成（终审）
│   └── llm.py              # LLM 客户端（重试 / JSON 修复）
├── renderer/
│   └── markdown.py         # 教辅 Markdown 渲染（含组件）
├── static/
│   └── index.html          # Web 前端
└── scripts/
    └── overnight_book_quality.py  # 全量批处理
```

## 7. 数据模型（摘要）

| 模型 | 层 | 用途 |
|---|---|---|
| `TimedChunk` | 0 | 分块后的字幕单元，带时间戳 |
| `KnowledgePoint` / `LectureDigest` | 1 | 一讲的压缩知识点地图 |
| `ComponentSpec` / `ChapterInstruction` / `BookPlan` | 2 | 主编的蓝图 |
| `ChapterSection` / `LectureDraft` | 3 | 一章的产物（含组件实例和时间链接） |
| `CourseBook` | 4 | 全书产物 |

## 8. MVP 范围

### 8.1 已完成

| 功能 | 说明 |
|---|---|
| 字幕获取 | 从智云课堂拉讲次、字幕，带缓存 |
| 字幕清洗分块 | 确定性逻辑，去口头语、按时间和长度分块 |
| 字幕压缩 | 每讲 → 知识点地图 |
| 全书规划 | 结构 + 组件规范 + 每章指令 + 系统 prompt |
| 分章撰写 | 教辅章节，带时间戳链接和组件 |
| 全书合成 | 前言 / 知识地图 / 术语表 / 要点索引 |
| 网页展示 | 组件化渲染，目录 + 正文 |
| 导出 | Markdown |

### 8.2 待做 / 可增强

| 功能 | 说明 |
|---|---|
| 全课端到端验证 | 14 讲全量重跑 + 质量验收 |
| PDF 导出 | 省略时间戳链接，静态排版 |
| 前端组件化 | Tips / 例题 / 侧边栏的 HTML 形态 |
| 单讲重生成 | CLI 已支持，前端待接入 |

### 8.3 不做

| 功能 | 理由 |
|---|---|
| PPT / OCR / 字幕-PPT 对齐 | 暂不处理，当前只使用字幕 |
| 多轮聊天作为主产品 | 稀释"课程成书"主线 |
| 个性化掌握度 | 需要学生行为数据，太重 |
| 自训模型 | 时间和数据都不匹配 |
| 全校课程平台 | 比赛作品不需要平台级扩展 |

## 9. 技术依赖

### 9.1 数据获取

- zju-scholar（`~/.cielagent/skills/zju-scholar`）：智云课堂课程列表、讲次、字幕。

### 9.2 大模型

- 通过 OpenAI 兼容端点调用（`.env` 中的 `LLM_BASE_URL` / `LLM_MODEL`）。
- 用于生成工作流：压缩、规划、写作、合成。
- 不需要自训模型。

### 9.3 前端

前端要求很低：课程选择、生成按钮、进度、教辅阅读区、导出按钮。比赛演示时丝滑比复杂重要。

## 10. 比赛展示策略

### 10.1 演示脚本

```text
1. 这是某门真实课程的智云课堂页面。
2. 我们只输入/选择这门课程。
3. 系统自动获取它的字幕。
4. 生成工作流把课堂口语整理成知识单元和教辅章节。
5. 最终生成一本有目录、重点、易错点、来源的结构化教辅。
6. 打开网页，可以按章阅读，点击时间戳跳回课堂原讲解。
7. 教师可以把它作为讲义草稿，学生可以把它作为复习材料。
```

### 10.2 申报书话术

> 本作品聚焦高校课堂教学过程资料难以沉淀的问题，基于智云课堂字幕资源，构建课程教辅生成智能体。智能体自动完成课程资源获取、字幕清洗、知识点压缩、全书规划、分章撰写与终审合成，将课堂回放从"视频资源"转化为"结构化课程资产"。

不要说过满：

- 不要说"重构教育生态"。
- 不要说"完全替代教师备课"。
- 不要说"自动生成正式教材"。
- 可以说"教辅草稿""课程资产沉淀""辅助复习"。

### 10.3 版权口径

> 系统仅处理教师授权或学生本人有权限访问的课程资料，生成结果用于课程内部教学改进与个人学习，不默认公开原始字幕或完整课程内容。

## 11. 风险与兜底

| 风险 | 表现 | 兜底 |
|---|---|---|
| 字幕质量差 | ASR 错字、断句乱 | 清洗 + 保留原文引用 + 整理说明 |
| 大模型不稳定 | 超时、503、坏 JSON | 重试 + JSON 修复 + 启发式回退 |
| 上下文限制 | 全课字幕放不进一次调用 | 分层处理：主编只看压缩摘要，分章看完整字幕 |
| 生成内容胡编 | 模型扩写过度 | Prompt 限制 + 来源引用 + 审校 |
| 长课程生成慢 | 多讲次调用大模型耗时 | 缓存 + 后台任务 + 预生成样例 |
| 版权质疑 | 课程资料是否能整理 | 授权 / 权限内 / 不公开原始材料 |
| 现场网络不稳 | 无法实时拉取 | 预生成样例 + 缓存 |

```bash
uv sync                          # 安装依赖

uv run uvicorn coursebook_agent.app:app --host 127.0.0.1 --port 8000  # 起服务
uv run python -m coursebook_agent.cli --course-id 82493 --plan-only  # 全书蓝图

```

## 13. 给接手 AI 的规则

1. 先读本文档，不要建议做聊天机器人。
2. 项目目标是"课程 → 教辅书"，不是"学生 → 个性化学习画像"。
3. 输入必须极简：一门课。系统负责拿资料。
4. 输出必须极简：一本教辅。其他功能都是附属。
5. 提出新功能必须说明它如何增强成稿质量或演示效果。
6. 先做一门课，不要做全校平台。
7. 先做 Markdown，再考虑 PDF 排版。
8. 比赛里能顺滑演示比架构高级重要。
9. 任何改动都要跑测试：`uv run python -m unittest discover -s tests -v`。
