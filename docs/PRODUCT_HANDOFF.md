# CourseBookAgent 产品交接

> 2026-10-09。先读 `CURRENT_STATUS.md` 获取验证与缺口；产品思路简版见 `PRD.md`。代码事实见 `ARCHITECTURE.md` / `WORKFLOW.md`，协作见 `DEVELOPMENT.md`。

## 1. 目标与受众

学生上传课件、字幕、讲义和笔记，系统先理解各份资料，再规划整本书、分配资料、分章撰写并合成完整教辅。核心目标是可连续阅读、可复习的成稿，而非讲次摘要拼接。

学生是主要用户，教师和助教可审核草稿或沉淀讲义。上传自己的资料是主路径；智云课堂与学在浙大是浙大学生的便捷数据源，不能成为面向所有学生使用的前提。产品聚焦课程成书，不扩展为主聊天框、学生画像或全校平台。

## 2. 产品主路径

```text
建立资料集 → 上传/导入 → 选择资料版本并创建快照
          → 配置并启动生成 → 查看阶段与章节状态
          → 阅读产物 → 导出 Markdown
```

当前 8 个页面：资料库、资料集详情、工作流配置、运行中心、运行详情、产物列表、产物阅读、系统设置；导入是对话框，不是第 9 页。旧书架/工作台/阅读页已删除，旧 URL 由兜底重定向，不提供原有功能。

资料与投影调用 `/api/product/*`；生成、恢复/停止、下载与设置用共享 `/api/*`。HTTP `POST /api/generate` 必须提供 `snapshot_id`，不能单独传课程 ID。真实字段以 `API.md` 和代码为准。

## 3. 输入与输出

输入：PPTX、PDF、DOCX、Markdown、TXT 上传与文本解析；智云字幕/课件页导入；学在浙大原课件下载。解析以文本为主，不能声称扫描 PDF、图片、图表均可完整理解。校内接入依赖网络/会话/短信，演示准备可上传材料。

输出：结构化 CourseBook、Markdown 和网页阅读；包括导读、主题章节、例题/步骤/提醒、小结、前言、知识地图、术语与要点索引、来源与核验备注。PDF 确认稿为既有产物单独排版，系统 PDF 尚未接入。

## 4. 工作流与分工

快照确定使用哪些资料版本；七个运行阶段：解析 → 五栏目 description → 全书规划与 Tag → 按 Tag 装配 → 分章生成与章节检查 → 全书合成 → Markdown 渲染。

- 所有资料，包括字幕，均走 LLM description；失败才降级。
- 主 Agent 通过全部 description 规划主题章节、风格和 Tag；章数不等于讲次数。
- Tag 决定原资料进哪些章节，一份资料可服务多章；全局 Tag 进入各章，无 Tag 本次不使用。
- 系统组装 ChapterContext，章节 Agent 写正文；合成补充全书信息与前后衔接。
- 全书自动审稿/回炉仍是设计项，不能将章节审校称为事实认证。

产品层负责资料管理、版本、快照、运行生命周期和投影、阅读与导出入口；生成核心负责理解与成书策略。ADR 008 的职责边界仍适用，旧 API 兼容条款已被后续迁移取代。

## 5. 现状与下一阶段

16 份真实字幕已生成 12 章全书，已有完整 PDF 确认稿。用户认为片段内容质量高、接受阅读方向，准备交教师审核。尚未完成教师事实核验或无人干预稳定性验收。

下一阶段是比赛收尾：前端展示、续跑/保存验收、资料和成品预览、PDF 导出、可访问网页、简版 PRD、PPT 与录屏。不能把全书重写、全面自动审稿或无关扩展当成已接受任务。

恢复、保存和预览已有基础，应验收失败章重跑和历史版本一致性。实验台成品未自动成为产品 Job，需要明确接入方案。详细缺口见 `CURRENT_STATUS.md` / `ISSUES.md`。

## 6. 比赛表达

> 课程资料散落在课件、字幕和笔记里。学生上传这些资料，智能体通过全书规划、资料分配和分章撰写，将其整理成有知识结构、可阅读和可复习的课程教辅草稿。

以真实输入输出对照证明价值，以预生成成品和录屏支持演示。预生成、真实生成、人工重试、单独 PDF 排版和待核事实如实说明；不声称完整师生机协同、正式教材出版、全书自动审稿或播放器跳转。

公开范围需教师许可，默认不发布原始字幕、课件或完整课程。最新比赛材料和截止时间以官方后台/通知为准。

## 7. AI 接手

先核对状态和代码，不按旧问题单修复已删除页面。生成核心是队友工作线，改 prompt/模型/检查规则先说明影响。实验台用于逐阶段审核迭代，不随意变成普通用户前端。保留真实产物，不因交接重跑 LLM；数据与凭据不提交公开仓库。
