# CourseBookAgent 产品交接文档

> 交接对象：后续接手开发的 AI / 队友 / 参赛材料撰写者。
> 文档目的：即使不读取此前对话，也能理解这个"启真问智"教学智能体比赛项目要做什么、为什么做、输入输出是什么、工作流如何设计。

## 0. 一句话说明

**CourseBookAgent 是一个"课程成书"智能体：输入一门课程（从智云课堂或学在浙大导入，或者直接上传讲义），系统自动整理资料，经过 AI 生成工作流（字幕压缩 → 全书规划 → 分章撰写 → 全书合成），输出一份可阅读、可导出、像教辅书的课程讲义网页 / Markdown。**

```text
选择一门课程
    ↓
按 provider 导入：智云课堂 / 学在浙大 / 本地上传
    ↓
每讲压缩为知识点地图（面向聪明主编）
    ↓
全书规划（结构 + 组件规范 + 每章指令 + 写作系统 prompt）
    ↓
分章撰写（主编 prompt + 完整资料 → 教辅章节）
    ↓
全书合成（前言 + 知识地图 + 术语表 + 要点索引）
    ↓
输出教辅书（网页 / Markdown；PDF 尚未实现）
```

这个项目不是：

- 通用 ChatGPT 套壳。
- 复习陪伴机器人。
- 全校学习平台。
- 从零训练垂直大模型。
- 完整教学评价系统。

核心产品形态：**把一门真实课程自动整理成一本像样的教辅书。**

## 1. 比赛背景

比赛：第二届全国高校"启真问智"教育教学人工智能大赛。

- 赛道：教育教学智能体。
- 作品需基于国内通用大模型或平台工具开发 AI 智能体。
- 关注真实教学场景、教学效率、个性化学习。

比赛叙事：

> 课堂视频、字幕、PPT 和讲义本来是碎片化、低复用的教学过程数据。CourseBookAgent 将这些过程数据自动整理为结构化课程教辅，让教师可以沉淀课程资产，让学生获得可阅读、可复习、可追溯的课程文本。

注意：比赛叙事可以写"师生机协同"，但产品不要被口号拖膨胀。MVP 先做"课程 → 教辅书"。

## 2. 产品切入点

### 2.1 真实问题

高校课程中，智云课堂与学在浙大沉淀了大量课堂录像、字幕、PPT 和讲义，但它们通常只是"回放资源"或"上传文件夹"：

- 学生复习时很难从数小时视频中快速重建知识结构。
- 老师的口述讲解不会自然沉淀为可复用讲义。
- PPT 只有框架，字幕只有口语流，两者分开看都不够完整。
- 学在浙大上传的 PDF/PPTX/DOCX 讲义分散在不同模块，没有统一管理。
- 人工整理一门课需要大量时间。

### 2.2 核心洞察

课堂材料不是缺内容，而是缺一次结构化加工。AI 的价值在于把课堂讲解整理成可阅读、有重点、可复习的课程文本。

### 2.3 产品定位

> **面向高校课程的 AI 教辅书生成工作流。**

不是"问答机器人优先"，而是"成稿优先"。如果后续要加问答、测验、复习功能，它们都应该依附在生成出的教辅上，而不是取代教辅成为主产品。

## 3. 用户与场景

### 3.1 目标用户

| 用户 | 诉求 | 本产品提供什么 |
|---|---|---|
| 任课教师 | 沉淀课程资产、整理讲义 | 自动生成课程教辅草稿 |
| 选课学生 | 快速复习、重建知识结构 | 有目录、有重点、有来源的课程教辅 |
| 助教/课程团队 | 整理课程资料 | 统一的资料管理 + 资料集 + 快照 |

### 3.2 核心场景

> 一门有智云课堂回放的课程 / 一份学在浙大课件集，被系统自动整理成一份可复习的教辅书。

演示流程：

1. 在资料库新建资料集。
2. 选择"智云课堂 / 学在浙大"，导入讲次或课件，或直接上传自己的 PPTX/PDF/DOCX/Markdown/TXT。
3. 选择本次生成所用的资料版本，创建输入快照。
4. 配置工作流（内置"课程教辅书" preset）。
5. 系统按快照运行；运行中心实时显示阶段、章节 Agent 状态、失败任务。
6. 打开产物阅读器查看生成的教辅书（按 Job ID 区分多个版本）。
7. 导出 Markdown；后续可重生成失败章节，复用成功快照。

## 4. 输入与输出

### 4.1 输入

最简输入：选定一个 `course_id`（智云课堂）或 `course_id`（学在浙大），或直接上传文件。

原则：**让用户先选/导入资料，再决定怎么用**。资料集可以长期保留，反复重用；快照保证每次运行引用版本可追溯。

### 4.2 输出

MVP 输出优先级：

1. **Markdown 教辅**：主产物，易于生成、版本管理、导出。
2. **网页阅读器**：比赛展示友好，支持组件渲染和时间戳跳转。
3. **PDF**：给老师/评委看的成品感（后置）。

教辅书结构：

```text
前言 / 如何使用 / 知识地图 / 学习路径 / 目录
第 N 讲：章节（承上 / 学习目标 / 导读 / 重点 / 概念 / 小节正文 / 易错点 / 小结 / 启下 / 来源）
要点速记 / 术语表 / 来源索引
```

质量底线：

- 像一本可复习的教辅书，不是散乱摘要。
- 每章结构一致，有承上启下。
- 有重点、有易错点、有例题。
- 尽量保留来源信息（字幕时间段）。
- 不胡乱扩写成教材，不假装老师没讲过的内容是课堂内容。

## 5. 核心 Workflow

```text
资料集（长期）
    ↓ 选取资源版本
输入快照（SHA-256 锁定）
    ↓ 提交运行
工作流预设（默认 coursebook）
    ↓
课程资料获取（按 provider：智云 / 学在浙大）
    ↓
字幕清洗分块（确定性逻辑）
    ↓
字幕压缩（每讲）
    ↓
全书规划（结构 + 组件规范 + 每章指令 + 系统 prompt）
    ↓
分章撰写（并发）
    ↓
质量门禁（组件契约 / 例子清理）
    ↓
全书合成
    ↓
渲染输出（Web / Markdown）
```

详细设计见 `docs/WORKFLOW.md`。

## 7. 数据模型（摘要）

### 生成核心

| 模型 | 层 | 用途 |
|---|---|---|
| `TimedChunk` | 0 | 分块后的字幕单元，带时间戳 |
| `KnowledgePoint` / `LectureDigest` | 1 | 一讲的压缩知识点地图 |
| `ComponentSpec` / `ChapterInstruction` / `BookPlan` | 2 | 主编的蓝图 |
| `ChapterSection` / `LectureDraft` | 3 | 一章的产物 |
| `CourseBook` | 4 | 全书产物 |

### 产品工作台

| 模型 | 用途 |
|---|---|
| `Dataset` | 资料集 |
| `Resource` / `ResourceRevision` | 资料与其版本（按 SHA-256 内容寻址） |
| `InputSnapshot` | 一次运行的资料版本快照 |
| `WorkflowPreset` | 工作流预设（默认 `coursebook`） |
| `AgentProjection` / `RunProjection` / `ArtifactSummary` | 运行与产物的结构化视图 |

## 9. 技术依赖

### 9.1 数据获取

- 项目内置智云适配器（`coursebook_agent/sources/zhiyun.py`）：智云课堂课程列表、讲次、字幕、PPT 时间轴。
- 项目内置学在浙大适配器（`coursebook_agent/sources/xuezai/assist.py`）：CAS 登录、我的课程、课件列表、原始文件下载。
- 智云可由 `.env` 中的 `ZHIYUN_JWT` 或 `ZHIYUN_SESSION_FILE` 提供会话；学在浙大通过设置页统一身份认证登录写入 `data/xuezai/session.json`。

### 9.2 大模型

- 通过 OpenAI 兼容端点调用（`.env` 中的 `LLM_BASE_URL` / `LLM_MODEL`）。
- 用于生成工作流：压缩、规划、写作、合成。
- 不需要自训模型。

### 9.3 前端

9 页产品工作台 + 旧兼容页，连接 `/api/product/*` 与旧 `/api/*`。

## 10. 比赛展示策略

### 10.1 演示脚本

```text
1. 打开资料库，新建一个资料集。
2. 选择智云课堂导入我的课程，挑一门真实课程，导入讲次字幕与课件页。
3. 切到学在浙大，再导入一门课程的原始 PPTX 讲义到同一资料集（演示多 provider）。
4. 上传一份学生笔记 PDF 或 Markdown 到资料集。
5. 在资料集详情选择本次要用的资料版本，创建输入快照。
6. 进入工作流配置页，确认内置"课程教辅书" preset 即可，无需调参。
7. 启动运行；运行中心实时显示阶段、章节 Agent 状态、失败任务。
8. 打开产物阅读器，展示目录、重点、易错点、来源。
9. 打开运行中心同课程的下一次生成（不同 Job ID），证明每次独立、互不覆盖。
10. 在系统设置切换统一身份认证登录，演示智云 + 学在浙大一次连上。
```

### 10.2 申报书话术

> 本作品聚焦高校课堂教学过程资料难以沉淀的问题，基于智云课堂字幕与学在浙大课件，构建课程教辅生成智能体。智能体自动完成课程资源获取、字幕清洗、知识点压缩、全书规划、分章撰写与终审合成，并通过资料集与输入快照让每次生成都可追溯、可复现、可重做。

不要说过满：

- 不要说"重构教育生态"。
- 不要说"完全替代教师备课"。
- 不要说"自动生成正式教材"。
- 可以说"教辅草稿""课程资产沉淀""辅助复习"。

### 10.3 版权口径

> 系统仅处理教师授权或学生本人有权限访问的课程资料，生成结果用于课程内部教学改进与个人学习，不默认公开原始字幕或完整课程内容。

## 11. 风险与兜底

| 风险 | 表现 | 兜底 |
|---|---|---|
| 字幕质量差 | ASR 错字、断句乱 | 清洗 + 保留原文引用 + 整理说明 |
| 大模型不稳定 | 超时、503、坏 JSON | 重试 + JSON 修复 + 启发式回退 |
| 上下文限制 | 全课字幕放不进一次调用 | 分层处理：主编只看压缩摘要，分章看完整字幕 |
| 生成内容胡编 | 模型扩写过度 | Prompt 限制 + 来源引用 + 审校 |
| 长课程生成慢 | 多讲次调用大模型耗时 | 缓存 + 后台任务 + 预生成样例 |
| 资料不齐 | 部分讲次缺字幕 | 当前：缺资料的讲次留空；后续：profile 切换 |
| 版权质疑 | 课程资料是否能整理 | 授权 / 权限内 / 不公开原始材料 |
| 现场网络不稳 | 无法实时拉取 | 预生成样例 + 缓存 |
| 跨平台账号冲突 | 智云 / 学在浙大各自会话 | 各自独立会话，登录失败互不阻塞 |

## 13. 给接手 AI 的规则

详细的分支、协作、验证和文档同步协议见 `docs/DEVELOPMENT.md`；本节只保留产品边界。

1. 先读本文档，不要建议做聊天机器人。
2. 项目目标是"课程 → 教辅书"，不是"学生 → 个性化学习画像"。
3. 输入要尊重资料集/快照分层：一门课或若干文件。系统负责按需引用。
4. 输出必须极简：一本教辅。其他功能都是附属。
5. 提出新功能必须说明它如何增强成稿质量、运行可观测性或演示效果。
6. 先做一门课，不要做全校平台。
7. 当前先做 Markdown 和 Web 阅读器，PDF 仍是后置能力。
8. 比赛里能顺滑演示比架构高级重要，但不能用预生成成品掩盖实时链路问题。
9. 任何改动都要跑后端测试；前端改动还要构建和 lint，详见 `docs/DEVELOPMENT.md`。
10. 产品层和生成核心的边界见 `docs/decisions/008-product-workbench-application-layer.md`；动生成核心前先看。
