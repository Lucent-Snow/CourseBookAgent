# CourseBookAgent 产品交接文档

> 交接对象：后续接手开发的 AI / 队友 / 参赛材料撰写者。  
> 文档目的：即使不读取此前对话，也能理解这个“启真问智”教学智能体比赛项目要做什么、为什么做、输入输出是什么、中间 workflow 如何设计。  
> 当前状态：四层教辅书生成工作流已实现，14 讲全部完成 book-aware 生成。

> 2026-07-23 范围说明：当前 MVP 暂不处理 PPT、OCR 和字幕-PPT 对齐，只使用智云课堂带时间戳字幕完成“单讲 → 全课 → Web 阅读器”闭环。本文中关于 PPT 的内容保留为后续增强方向，不属于当前关键路径。

---

## 0. 一句话说明

**CourseBookAgent 是一个“课程成书”智能体：输入一门课程，系统自动获取智云课堂字幕和 PPT，经过课程内容结构化工作流，输出一份可阅读、可导出的结构化课程讲义网页 / Markdown / PDF。**

最小闭环（四层工作流）：

```text
选择一门课程
    ↓
自动获取讲次、字幕
    ↓
Layer 1: 每讲压缩为知识点地图（面向聪明主编）
    ↓
Layer 2: 主编统筹（结构 + 组件规范 + 每章指令 + 系统 prompt）
    ↓
Layer 3: 分章撰写（系统 prompt + 主编指令 + 完整字幕）
    ↓
Layer 4: 终审合成（前言 + 知识地图 + 术语表 + 要点索引）
    ↓
输出教辅书网页 / Markdown / PDF
```

这个项目不是：

- 通用 ChatGPT 套壳。
- 复习陪伴机器人。
- 全校学习平台。
- 从零训练垂直大模型。
- 完整教学评价系统。

它的核心产品形态非常朴素：**把一门真实课程自动整理成一本像样的课稿 / 讲义。**

## 1. 比赛背景

比赛：第二届全国高校“启真问智”教育教学人工智能大赛。

关键信息：

- 赛道包括：教育教学垂直领域大模型、教育教学智能体。
- 本项目更适合走 **教育教学智能体** 赛道。
- 作品需基于国内通用大模型或平台工具开发 AI 智能体。
- 关注真实教学场景、教学效率、个性化学习、学习评价等。
- 特别关注实际教学场景落地效果及“师-生-机”协同体现。

本项目的比赛叙事：

> 课堂视频、字幕和 PPT 本来是碎片化、低复用的教学过程数据。CourseBookAgent 将这些过程数据自动整理为结构化课程讲义，让教师可以沉淀课程资产，让学生获得可阅读、可复习、可追溯的课程文本。

注意：比赛叙事可以写“师生机协同”，但产品不要被口号拖膨胀。MVP 先做“课程 → 讲义”。

## 2. 产品切入点

### 2.1 真实问题

高校课程中，智云课堂沉淀了大量课堂录像、字幕、PPT 时间轴，但它们通常只是“回放资源”：

- 学生复习时很难从数小时视频中快速重建知识结构。
- 老师的口述讲解不会自然沉淀为可复用讲义。
- PPT 只有框架，字幕只有口语流，两者分开看都不够完整。
- 如果人工整理，一门课需要大量时间。

### 2.2 核心洞察

课堂材料不是缺内容，而是缺一次结构化加工。

- PPT 提供课程骨架。
- 字幕提供教师讲解、例子、补充说明。
- AI 的价值在于把两者对齐后整理成可阅读的课程文本。

### 2.3 产品定位

> **面向高校课程的 AI 课程讲义生成工作流。**

不是“问答机器人优先”，而是“成稿优先”。

如果后续要加问答、测验、复习功能，它们都应该依附在生成出的讲义上，而不是取代讲义成为主产品。

## 3. 用户与场景

### 3.1 目标用户

| 用户 | 诉求 | 本产品提供什么 |
|---|---|---|
| 任课教师 | 沉淀课程资产、整理讲义、复盘教学内容 | 自动生成课程讲义草稿，减少整理成本 |
| 选课学生 | 快速复习、重建知识结构、查找课堂讲解 | 有目录、有章节、有来源的课程文本 |
| 助教/课程团队 | 整理课程资料、维护课程知识库 | 统一的课程资料处理工作流 |

### 3.2 核心场景

MVP 场景只保留一个：

> 一门已经有智云课堂回放和 PPT 的课程，被系统自动整理成一份结构化讲义。

演示时也只演这个：

1. 选择课程。
2. 展示系统正在获取讲次、字幕、PPT。
3. 展示生成中的 workflow 状态。
4. 打开最终讲义网页。
5. 导出 Markdown / PDF。

## 4. 输入与输出

### 4.1 输入

最简输入：

```text
course_id 或 course_name
```

实际系统可能需要：

| 输入项 | 来源 | 是否用户手动提供 |
|---|---|---|
| 课程 ID / 课程名称 | 智云课堂 / zju-scholar | 用户选择或预设 |
| 讲次列表 | 系统自动获取 | 否 |
| 字幕 transcript | 系统自动获取 | 否 |
| PPT / 课件页 / 时间轴 | 系统自动获取 | 否 |
| 课程元信息 | 系统自动获取 | 否 |

原则：**不要让用户上传一堆资料。**

输入越简单，产品越像智能体：用户只说“这门课”，系统自己去拿材料。

### 4.2 输出

MVP 输出优先级：

1. **Markdown 讲义**：最容易生成、版本管理、导出。
2. **网页阅读器**：比赛展示友好。
3. **PDF**：给老师/评委看的成品感。

目标输出结构：

```text
课程标题
课程简介 / 生成说明
目录

第 1 讲：标题
    1.1 本讲概述
    1.2 核心概念
    1.3 教师讲解整理
    1.4 例子与课堂补充
    1.5 本讲小结
    来源：字幕时间段 / PPT 页

第 2 讲：标题
...

附录
- 术语表
- 全课知识点索引
- 讲次来源索引
```

质量底线：

- 像一份可阅读的讲义，不是散乱摘要。
- 每章结构一致。
- 尽量保留来源信息。
- 不胡乱扩写成教材，不假装老师没讲过的内容是课堂内容。

## 5. 核心 Workflow

```text
课程选择
    │
    ▼
课程资料获取
- 获取课程信息
- 获取讲次列表
- 获取每讲字幕
- 获取 PPT / 课件页 / 时间轴
    │
    ▼
资料标准化
- 字幕清洗：去口头语、修正断句、去重复
- PPT 标准化：页码、标题、图片/文字、时间点
- 讲次元数据：日期、标题、教师、时长
    │
    ▼
字幕-PPT 对齐
- 用时间轴对齐
- 或用标题/关键词弱对齐
- 对齐失败时保留“仅字幕/仅 PPT”标记
    │
    ▼
知识单元切分
- 按 PPT 页 / 主题 / 时间段切分
- 提取概念、定义、例子、重点
    │
    ▼
单讲讲义生成
- 本讲概述
- 小节结构
- 正文整理
- 小结
- 来源引用
    │
    ▼
全课成书
- 合并目录
- 统一术语
- 去重复
- 风格统一
- 生成附录
    │
    ▼
输出
- Markdown
- 网页
- PDF
```

```text
├── agent/
│   ├── outline.py          # 生成目录与讲次结构

│   ├── refine.py           # 全课统一、去重、润色
│   └── citations.py        # 来源引用与可追溯信息
```

## 7. 数据模型草案

### 7.1 Course

```python
@dataclass
class Course:
    course_id: str
    name: str
    teacher: str | None
    term: str | None
    source: str = "zhiyun"
```

### 7.2 Lecture

```python
@dataclass
class Lecture:
    lecture_id: str
    course_id: str
    title: str
    index: int
    date: str | None
    duration: int | None
```

### 7.3 TranscriptSegment

```python
@dataclass
class TranscriptSegment:
    lecture_id: str
    start: float
    end: float
    text: str
```

### 7.4 Slide

```python
@dataclass
class Slide:
    lecture_id: str
    page: int
    timestamp: float | None
    image_path: str | None
    text: str | None
    title: str | None
```

### 7.5 KnowledgeUnit

```python
@dataclass
class KnowledgeUnit:
    lecture_id: str
    title: str
    summary: str
    transcript_refs: list[str]
    slide_refs: list[str]
```

```python
@dataclass
class CourseBook:
    course: Course
    title: str
    chapters: list[BookChapter]
    glossary: list[GlossaryItem]
    output_paths: dict[str, str]
```

## 8. MVP 范围

### 8.1 P0：必须完成

| 功能 | 说明 |
|---|---|
| 课程选择 | 可以先写死一门示范课，也可以从“我的课程”中选择 |
| 字幕获取 | 调用现有 zju-scholar 智云能力获取 transcript/lecture 文本 |
| PPT 获取 | 调用现有 zju-scholar 导出 PPT/PDF/课件页能力 |
| 单讲处理 | 至少能对一讲生成结构化讲义 |
| 全课合并 | 能把多讲合并成一份 Markdown |
| 网页展示 | 能打开生成结果，带目录和正文 |
| 导出 | 至少支持 Markdown；PDF 可后置 |

### 8.2 P1：展示加分

| 功能 | 说明 |
|---|---|
| 来源引用 | 每节后显示来自第几讲、字幕时间段、PPT 页 |
| 生成进度 | 前端显示：获取中、清洗中、生成中、完成 |
| 术语表 | 自动提取关键概念 |
| 章节重生成 | 对某一讲重新生成 |
| PDF 导出 | 增强成品感 |

### 8.3 不做

| 功能 | 理由 |
|---|---|
| 多轮聊天作为主产品 | 容易变成普通 RAG Chat，稀释“课程成书”主线 |
| 个性化掌握度 | 需要学生行为数据，MVP 太重 |
| 自训模型 | 时间和数据都不匹配 |
| 全校课程平台 | 比赛作品不需要先做平台级扩展 |
| 复杂教师端 | 老师只需要看到成稿和导出，不需要后台系统 |

## 9. 技术依赖

### 9.1 已有能力

可复用 `zju-scholar`：

- 智云课堂课程列表。
- 视频 / 讲次元数据。
- 字幕 transcript / lecture 文本。
- PPT 时间轴。
- courseware-pdf 导出。

### 9.2 大模型

用于：

- 字幕清洗辅助。
- 知识点提取。
- 单讲讲义生成。
- 全课目录生成。
- 风格统一与去重。

不需要自训模型。

### 9.3 前端

前端要求很低：

- 课程选择区。
- 生成按钮。
- 进度状态。
- 讲义阅读区。
- 导出按钮。

比赛演示时，**丝滑比复杂重要**。

## 10. 比赛展示策略

### 10.1 现场演示脚本

```text
1. 这是某门真实课程的智云课堂页面。
2. 我们只输入/选择这门课程。
3. 系统自动获取它的字幕和 PPT。
4. 工作流把课堂口语和 PPT 框架整理成知识单元。
5. 最终生成一份结构化课程讲义。
6. 讲义中可以看到目录、章节正文、重点概念，以及来源信息。
7. 教师可以把它作为讲义草稿，学生可以把它作为复习材料。
```

### 10.2 申报书话术

可以写：

> 本作品聚焦高校课堂教学过程资料难以沉淀的问题，基于智云课堂字幕与课件资源，构建课程讲义生成智能体。智能体自动完成课程资源获取、字幕清洗、课件对齐、知识单元切分与讲义成稿生成，将课堂回放从“视频资源”转化为“结构化课程资产”。

不要写得过满：

- 不要说“重构教育生态”。
- 不要说“完全替代教师备课”。
- 不要说“自动生成正式教材”。
- 可以说“讲义草稿”“课程资产沉淀”“辅助复习”。

### 10.3 版权说法

建议统一口径：

> 系统仅处理教师授权或学生本人有权限访问的课程资料，生成结果用于课程内部教学改进与个人学习，不默认公开原始字幕、PPT 或完整课程内容。若用于公开出版或商业传播，需要获得课程资料权利方授权。

## 11. 风险与兜底

| 风险 | 表现 | 兜底 |
|---|---|---|
| 字幕质量差 | ASR 错字、断句乱 | 清洗 + 保留原文引用 |
| PPT 获取失败 | 课件无权限或接口变化 | 退化为仅字幕生成，并标记缺失 |
| 对齐失败 | 字幕和 PPT 时间轴不一致 | 改为按讲次/关键词弱对齐 |
| 生成内容胡编 | 模型扩写过度 | Prompt 限制“只能基于资料”；保留来源 |
| 长课程生成慢 | 多讲次调用大模型耗时 | 先支持单讲/选定讲次；后台任务 |
| 版权质疑 | 课程资料是否能整理 | 强调授权/权限内/不公开原始材料 |
| 现场网络不稳 | 无法实时拉取 | 准备预生成样例和录屏 |

## 12. 下一步开发顺序

1. **确定示范课**：先锁一门有字幕、有 PPT 的真实课程。
2. **跑通数据获取**：用 zju-scholar 拉讲次、字幕、PPT。
3. **生成单讲 Markdown**：先不要做全课。
4. **生成全课 Markdown**：统一目录和章节格式。
5. **做最小网页阅读器**：渲染 Markdown 或 JSON。
6. **加来源引用**：每节标出讲次、时间段、PPT 页。
7. **准备比赛演示样例**：预生成一份成品，防止现场翻车。

## 13. 给接手 AI 的规则

1. 先读本文档，不要上来建议做聊天机器人。
2. 项目目标是“课程 → 讲义”，不是“学生 → 个性化学习画像”。
3. 输入必须极简：一门课。系统负责拿资料。
4. 输出必须极简：一份讲义。其他功能都是附属。
5. 如果要提出新功能，必须说明它如何增强成稿质量或演示效果。
6. 先做一门课，不要做全校平台。
7. 先做 Markdown，不要先纠结 PDF 排版。
8. 比赛里能顺滑演示比架构高级重要。
